# Release 4.0.22 verification

Verified on October 16, 2026, using Java 21.0.10 and Minecraft 1.21.1.

| Check | Result | Local evidence (ignored build output) |
| --- | --- | --- |
| NeoForge and Fabric production builds | Both succeeded | `build/release-4.0.22-build-final.log` |
| Release metadata, unique ZIP entries and JSON validity | Both main archives passed; 3,962 JSON entries per archive | `build/release-4.0.22-audit.json` |
| Approved artwork and recipe contents | All 14 artwork files match the approved local revisions; all eight recipes match PR #6 | `build/release-4.0.22-audit.py` |
| Development-source/resource isolation | All six main, source and dev-shadow archives passed | `tests/starfield/verify_release.py` |
| Final NeoForge JAR geometry and gameplay checks | 134/134 passed: 126 shape checks plus eight recipe checks | `build/release-4.0.22-validation/server/shape-results.txt` |

The final production NeoForge JAR was installed on an ordinary dedicated server with NeoForge 21.1.226 and Resourcefulconfig 3.0.11. The verification mod is separate and is not included in either release JAR.

For wooden, iron and obsidian crop sticks, the probe reads the actual JSON models from the production JAR, resolves their parents, builds the union of their cuboids and compares it with the selection and collision shapes. It checks all four crop states, single and double sticks, and the planted-stick outline's clipping at ground level. The configuration method returns no collider when collisions are disabled, while selection is retained. That branch is called directly because Minecraft caches block-state collision shapes; live configuration switching was not changed or claimed as tested.

The server's `Level.clip` checks OUTLINE and COLLIDER rays through each moved crossbar and through its former position. `Level.noCollision` confirms physical obstruction on the new bars and open space at the old positions and in the center. These checks use the game's block-collision queries, not comparisons of source text alone.

All eight revised recipes resolve their ingredients and match their crafting inputs through the loaded server RecipeManager. Their grid dimensions, assembled output identifiers and counts are checked, including three hollow irrigation channels and 2×2 magnifying-glass/trowel recipes.

The same artwork and collision code was inspected in the manual NeoForge client before the version bump. The final 4.0.22 JAR was checked on the dedicated server. Fabric passed production build and archive checks; a Fabric gameplay session and unrelated integration suites were not run for this patch.

The data generator completed all providers and reported its output cache, but its development launcher stayed alive on idle non-daemon worker threads after the main method returned. That owned process was stopped after completion; the separate production build then completed successfully. The diagnostic log and thread dump are retained as `build/release-4.0.22-build.log` and `build/release-4.0.22-datagen-threads.txt`. Recipe data remains handwritten; the inactive legacy recipe provider was synchronized without enabling it.

PR #6's original commits by [12lewisFTW](https://github.com/12lewisFTW) are preserved in the default branch. The approved maintainer artwork revisions override the later PR artwork where they differ. Contributor credit is also recorded in the artwork commit, README, changelog and release notes.
