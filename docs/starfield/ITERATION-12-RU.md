# Итерация 12 — семенной аппарат и автоматический сбор

Дата: 9 октября 2026 года. Основа: официальный Starfield Pastoral `0.6.3fix1`, commit `df2151c66a2a9c02855e4db23108e57c422ce78e`, Minecraft 1.21.1 / NeoForge 21.1.226. Продолжение [итерации 11](ITERATION-11-RU.md).

## Наследственный цикл

Основные продукты ручного, косового и автоматического сбора получают отдельный компонент `agricraft:starfield_produce` внутри `CUSTOM_DATA`: версия схемы, исходный посадочный вид, фактический предмет и полный стандартный геном AgriCraft с обоими аллелями. Нативное качество, варианты продукта и посторонние компоненты сохраняются. Побочные семена подсолнуха, сено и другие добавочные предметы не получают геном основного продукта. Выращенный из сезонных диких семян forage сохраняет именно исходный сезонный вид. Природный forage и гигантский урожай остаются без наследственного компонента.

Семенной аппарат по-прежнему выполняет свой рецепт, детерминированный бросок, расход одного продукта, длительность и выбор количества семян. Интеграция обрабатывает **окончательный** план после обоих нативных конвейеров сторонних преобразований, до расходования входа. При совпадении выбранного предмета семян с исходным посадочным видом переносится полный геном. Редкий результат ancient fruit seeds, mixed seeds и семена другого вида не наследуют чужой геном; количество семян не получает бонус урожайности.

У нативного resolver есть существенная особенность: виноград даёт summer seeds. Геном обычного grape crop не переносится на летние дикие семена. Продукт летнего wild seed, напротив, может вернуть его исходный геном. Специальные соответствия sweet gem berry → rare seed, unmilled rice → rice shoot и Qi fruit → Qi bean остаются нативными. Запрет семенного аппарата для coffee bean/fiber не обходится.

Проверяются схема, исходный вид, соответствие предмета и структура генома. Повреждённый или неизвестный наследственный компонент отклоняет запуск до расходования входа. Продукт без компонента обрабатывается как обычный нативный продукт; старые запасы и продукция гиганта не восстанавливают выдуманных родителей. Вино, сушёные фрукты и прочие результаты обычных timed machines сохраняют нативные свойства без генома растения. Удаляются только собственные поля наследственности из результата, включая случай, когда сторонний провайдер скопировал их на неподходящий предмет.

Выбранные семена и их геном хранятся в настоящем `SeedMakerBlockEntity`. Повторная загрузка не вычисляет результат заново. Существующие симуляция вставки/извлечения, частичная выдача и завершение цикла продолжают работать с нативным количеством и сроком.

## Автоматика

Добавлены общий необязательный `ExternalHarvestSupport` и `AgriApi.harvest(level, pos, output)`. Обычные AgriCraft crops используют прежний сбор; поддержанные нативные культуры вызывают настоящий `StardewCropRuntime.harvestForAutomation`. Интеграция Create отменяет дальнейший общий срез/пересадку для распознанного нативного растения, включая отказ по зрелости или неподдержанному действию. Адаптеры PneumaticCraft и Industrial Foregoing используют тот же вход; их игровые механизмы отдельно не запускались.

Контекст сохраняется нативным: `AUTOMATION`, без игрока, подставного инструмента и земледельческого опыта. Внешний вход AgriCraft/Create передаёт farming level 0. Собственные Junimo и прямые вызовы Starfield API сохраняют переданный ими farming level. Нативный Junimo-путь допускает обычные культуры с косовым сбором, включая wheat; это разрешение автоматики, а не превращение механизма в игрока с косой. Ручные требования инструмента остаются прежними.

Результаты `tryHarvestByJunimo` сначала собираются внутри общей границы сбора. Нативный код один раз изменяет корень/обе части и повторное созревание, затем проверяется завершённость перехода. Основные продукты получают геном и существующий бонус gain один раз, со стандартным разделением переполненных стеков. Качество, нативные броски и побочные продукты сохраняются. Исключение до выдачи восстанавливает обе части, посадочную запись и нативный прогресс, не выдавая накопленных результатов. Немедленный повторный вызов по верхней или нижней части не собирает второй урожай.

Контракт внешнего получателя — принять каждый полный стек. Если произвольный получатель уже принял предмет и затем выбросил исключение, откатить его инвентарь через `Consumer<ItemStack>` невозможно. Растение остаётся собранным, ошибка передаётся вызывающему коду; повторное использование растения для дублирования запрещено. Автоматический откат произвольного стороннего инвентаря и компенсация отменённых им выдач не заявляются.

Нативный crop API этой версии не собирает зрелый forage, требующие отдельного действия корни и гиганты. Для AgriCraft/Create они имеют явный статус `UNSUPPORTED`: общий разрушительный fallback не запускается. Неизвестные/повреждённые sidecar-данные и декоративные посадки тоже не разрешают такой обход. Рост, календарь, модели и правила гигантов остаются у Starfield.

## Проверки

Полный обычный enabled-профиль прошёл **120 обязательных GameTest**, включая 14 новых проверок производства/автоматики и два запуска настоящего `HarvesterMovementBehaviour`. Отдельные JVM write/read прошли **по 77 обязательных проверок**. В новом checkpoint первая JVM оставляет настоящий семенной аппарат с уже выбранной продукцией; вторая читает блок/инвентарь из мира, сравнивает геном, количество и абсолютный срок, извлекает семена один раз и повторно сажает их. Свидетель не восстанавливает ни аппарат, ни его предметы. Нативные crop/forage/giant checkpoint предыдущих этапов тоже прошли.

Перезапуск использует отдельный профиль без общего теста полива: тот вызывает суточную обработку всех растений мира и после записи свидетельств может продвинуть другие контрольные посадки. Полный регрессионный запуск выполняется без restart phase. В повторяемом fixture полива восстанавливается нативная энергия тестового игрока перед оплачиваемым действием; производственная стоимость инструмента не меняется. Перед новым write аппарата старый блок fixture удаляется, чтобы повторный запуск не использовал прежний незавершённый цикл.

Профили `starfieldAutomationTests` и `starfieldCreateTests` включаются только при разработке; второй добавляет настоящий Create 6.0.10-280, Ponder 1.0.82, Flywheel 1.0.6 и Registrate MC1.21-1.3.0+67. Изоляция двух профильных архивов подтверждена. Инструкции запуска находятся в [tests/starfield/README.md](../../tests/starfield/README.md); журналы — игнорируемые `build/starfield-iteration0/iteration12-*.log`. Официальный JAR повторно проверен по размеру/SHA-256, 251 исходный файл — по Git blob закреплённого commit.

`git diff --check` прошёл. Проверки включают отказ выдачи и намеренно выбрасываемые исключения; соответствующие записи rollback/error в журналах отрицательных сценариев ожидаемы. Проверки выключенной/отсутствующей интеграции подтверждают неактивный общий harvest-provider и сохранение исходных операций через facade; Fabric не получает NeoForge bridge.

Графический клиент, анимация движения реальной конструкции и игровое отображение жердочек вручную не проверялись. Версия мода остаётся 4.0.19; публикация не выполнялась. Следующий этап — [итерация 13: регрессия, миграции и подготовка выпуска](../STARFIELD-COMPAT-PLAN-RU.md).
